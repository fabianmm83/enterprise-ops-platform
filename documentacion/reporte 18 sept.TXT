Documentación Técnica — Enterprise Operations Platform
Voy a explicarte todo lo que tienes de forma técnica, capa por capa, como si estuvieras en una entrevista técnica o en un onboarding de equipo.

1. Visión general del sistema
Enterprise Operations Platform es una API REST backend para gestión de operaciones empresariales internas: usuarios, roles, proyectos, tareas y auditoría.

Decisiones de diseño
UUID como PK (no auto-increment) → mejor para sistemas distribuidos, evita enumeración

Enums como VARCHAR (no ordinal) → legibilidad en BD, tolerante a reordenamientos

created_at / updated_at con TIMESTAMP WITH TIME ZONE → sin problemas de zonas horarias

Auditoría automática con @CreatedDate / @LastModifiedDate de Spring Data

Foreign keys con ON DELETE RESTRICT/CASCADE/SET NULL → integridad referencial explícita

Estructura del JWT
Access Token payload:

json
{
  "type": "access",
  "authorities": ["ROLE_USER"],
  "sub": "test@example.com",
  "iss": "enterprise-ops-platform",
  "iat": 1789774329,
  "exp": 1789775229
}
Algoritmo: HS512 (HMAC + SHA-512)

Firma: con signingKey derivada del JWT_SECRET (Base64)

Duración: 15 minutos (900000 ms)

Refresh token: mismo formato pero "type": "refresh", 7 días

6. Seguridad — detalles técnicos
SecurityConfig
java
@Configuration
@EnableMethodSecurity   // habilita @PreAuthorize
public class SecurityConfig {

    @Bean
    public SecurityFilterChain securityFilterChain(HttpSecurity http) {
        return http
            .csrf(AbstractHttpConfigurer::disable)      // JWT es stateless
            .cors(cors -> cors.configurationSource(...)) // CORS explícito
            .sessionManagement(session ->
                session.sessionCreationPolicy(STATELESS)) // sin sesiones HTTP
            .authorizeHttpRequests(auth -> auth
                .requestMatchers("/api/v1/auth/**", "/swagger-ui/**", ...).permitAll()
                .anyRequest().authenticated())
            .authenticationProvider(authenticationProvider())
            .addFilterBefore(jwtAuthFilter, UsernamePasswordAuthenticationFilter.class)
            .build();
    }
}
Decisiones clave:

Decisión	Razón
csrf disable	JWT no usa cookies de sesión, así que CSRF no aplica
STATELESS	No guardamos sesiones, cada request se autentica con JWT
@EnableMethodSecurity	Permite @PreAuthorize("hasRole('ADMIN')") en controllers
CORS explícito	Solo permite orígenes conocidos (localhost:5173, etc.)
Filtro JWT antes de UsernamePasswordAuthenticationFilter	Nuestro filtro corre primero y setea el SecurityContext
Rutas públicas vs protegidas
Ruta	Acceso
/api/v1/auth/**	Público
/v3/api-docs/**	Público
/swagger-ui/**	Público
/actuator/health	Público
/actuator/info	Público
OPTIONS /**	Público (preflight CORS)
Todo lo demás	Requiere JWT
BCrypt
java
@Bean
public PasswordEncoder passwordEncoder() {
    return new BCryptPasswordEncoder(12);
}
Strength 12 = 2^12 = 4096 iteraciones. Balance entre seguridad (~250ms) y UX.

CustomUserDetailsService
java
public UserDetails loadUserByUsername(String email) {
    User user = userRepository.findByEmail(email).orElseThrow(...);
    return User.builder()
        .username(user.getEmail())
        .password(user.getPassword())
        .disabled(!user.getActive())
        .authorities(List.of(new SimpleGrantedAuthority("ROLE_" + user.getRole().name())))
        .build();
}
Nota: Spring Security requiere el prefijo ROLE_ cuando usas hasRole().

14. Decisiones técnicas clave (para entrevistas)
Decisión	Alternativa	Por qué
PostgreSQL	MySQL, MongoDB	Relacional para operaciones empresariales, JSONB futuro, robusto
Flyway	Liquibase, Hibernate ddl-auto	Versionado en SQL puro, reproducible, sin magia
JWT	Sesiones HTTP	Stateless, escala horizontal sin sesiones compartidas
Access + Refresh tokens	Solo access	Balance seguridad/UX. Access corto (15m), refresh largo (7d)
DTOs con records	Clases	Inmutabilidad, menos boilerplate, Java 21 idiomático
@EntityListeners	Triggers SQL	Auditoría a nivel aplicación (más flexible)
Layered architecture	Hexagonal, DDD	Suficiente para MVP, fácil de migrar a hexagonal después
UUID	Long autoincrement	Distribuible, no enumerable, mejor para APIs públicas
BCrypt(12)	Argon2, scrypt	Estándar, bien soportado, 250ms razonable

17. Diferenciadores técnicos del proyecto
Cuando estés en una entrevista, esto es lo que hace especial tu proyecto:

Java 21 + Spring Boot 4 — stack de vanguardia (no el típico tutorial con Java 11 + Spring Boot 2)

Arquitectura por capas con separación estricta — controllers, services, repositories, DTOs

JWT con access + refresh tokens — patrón de producción, no tutorial básico

Migraciones versionadas con Flyway — no ddl-auto: update (anti-pattern común)

@RestControllerAdvice global — manejo de errores centralizado y consistente

BCrypt strength 12 — hashing con costo computacional adecuado

Bean Validation en DTOs, no en entidades — separación de responsabilidades

CORS explícito con orígenes conocidos, no *

Records de Java 21 para DTOs inmutables — código idiomático moderno

Docker Compose con healthcheck y volumen persistente

Documentación Swagger/OpenAPI integrada con anotaciones

Auditoría automática con @CreatedDate / @LastModifiedDate

README profesional con badges, arquitectura y roadmap

Convenciones de commits (Conventional Commits: feat, chore, docs)

Estructura escalable — fácil agregar Projects, Tasks, AuditLogs
